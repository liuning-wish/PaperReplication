
# 论文复现项目说明

## 一、项目简介

# 论文复现报告On the semantic representation of risk
> Wulff, D. U., & Mata, R. (2022). On the semantic representation of risk.Science Advances, 8(13), eabm1883.
> DOI：https://doi.org/10.1126/sciadv.abm1883

项目分为两条分析路线：

一是基于作者提供的节点数据开展分析

二是基于自行计算得到的 MyNode 节点数据开展分析。

项目包含原始输入数据、中间数据、分析脚本、结果图形以及 Quarto 报告。


## 二、项目文件结构

```text
PaperReplication/
├── PaperReplication.Rproj
├── README.md
├── Report.qmd
├── Report.html
├── Data/
│   ├── InputData/
│       ├── Metadata/
│   │       └── Data_Sources_Guide.md
│   └── IntermediateData/
│       ├── AuthorNode/
│       └── Mynode/
├── Scripts/
│   ├── Shared/
│   ├── MyNode/
│   └── AuthorNode/
└── Output/
    └── Results/
        ├── Mynode/
        └── authornode/
```

主要文件和文件夹的用途如下：

- `Data/InputData/`：存放分析所需的输入数据。
- `Data/IntermediateData/`：存放分析过程中生成或使用的中间数据及预计算结果。
- `Data/IntermediateData/AuthorNode/`：存放作者节点数据分析路线使用或生成的中间数据。
- `Data/IntermediateData/Mynode/`：存放自行计算节点数据的分析路线使用或生成的中间数据。
- `Scripts/Shared/`：存放两条分析路线共用的辅助函数及相关代码。
- `Scripts/MyNode/`：存放基于自行计算的节点数据开展分析的脚本。
- `Scripts/AuthorNode/`：存放基于作者节点数据开展分析的脚本。
- `Output/Results/Mynode/`：存放 MyNode 分析路线生成的图形和结果。
- `Output/Results/authornode/`：存放作者节点数据分析路线生成的图形和结果。
- `Report.qmd`：Quarto 报告源文件。
- `Report.html`：渲染生成的 HTML 报告。
- `README.md`：项目说明文件。

## 四、运行环境与依赖

本项目使用 R 语言进行数据处理、网络分析和结果可视化，使用 RStudio 作为主要开发环境，并使用 Quarto 生成 HTML 报告。

项目脚本涉及数据处理、网络分析、图形绘制及 C++ 扩展等功能。根据实际脚本，相关依赖包括 `tidyverse`、`igraph`、`Rcpp`、`openxlsx` 等 R 包。

具体依赖应以各脚本中的 `library()`、`require()` 调用及项目实际运行环境为准。运行前应确认所需软件包已经安装，并且 `Scripts/Shared/` 中的辅助文件可以正常调用。

## 五、项目运行与结果查看

### 5.1 打开项目

使用 RStudio 打开 `PaperReplication.Rproj`，使项目根目录成为工作目录。运行脚本前，应检查数据文件路径和输出目录是否与当前项目结构一致。

### 5.2 运行分析脚本

根据复现任务的需要，分别运行 `Scripts/AuthorNode/` 和 `Scripts/MyNode/` 中的相关脚本。

- 作者节点数据路线使用作者提供的节点数据或相关预计算结果开展分析。
- MyNode 路线使用自行计算得到的节点数据开展后续分析。

具体执行顺序应以各脚本之间的数据依赖关系为准。部分分析涉及网络聚类和 Bootstrap 重抽样，可能需要较长的计算时间。

### 5.3 查看分析结果

分析产生的图形和结果主要保存在 `Output/Results/` 下对应的子目录中；中间数据保存在 `Data/IntermediateData/` 下。

无需重新执行全部分析，即可直接使用浏览器打开已有的 `Report.html` 查看复现报告。

## 六、本项目做出的修改说明）

本项目的修改主要用于适配 Windows 环境、修复运行报错和规范文件路径，尽量保留原作者的核心分析流程。具体修改如下：

1. Bootstrap 并行计算适配： 原代码使用 `makeForkCluster()` 进行并行计算，该方式不适用于 Windows，因此改为串行循环执行 Bootstrap 任务。

2. 稳定性分析报错修复：原代码使用固定长度 205 补齐聚类结果，但 MyNode 部分结果的群组数量最高达到 212。为避免负数长度报错，改为通过 `max_clusters` 动态确定补齐长度，并保留原有结果合并步骤。

3. 节点频数计算修复： 对 `frequency_wave_1` 和 `frequency_wave_2` 的频数结果使用 `as.numeric()` 转换，避免 `table` 对象的数据类型影响后续分析。

4. 边权重处理： 对小于或等于 0 的 `cl_weight` 替换为极小正数 `1e-8`，以减少后续网络分析中的报错风险。该调整可能影响相关计算，需在结果核对时予以关注。

5. 跨语言绘图修复： 调整 Figure 5 中 `cs` 及相关绘图参数的定义顺序，解决函数执行时无法找到对象的问题。

6. 文件路径整理：统一数据读取、结果导出和图片保存路径，分别整理 `AuthorNode` 与 `MyNode` 两条分析路线，避免输入输出混淆。

完成相关调整后，项目中的相应分析脚本能够运行，并成功生成相关图形。需要注意，程序正常运行不代表所有结果均已完全复现；两条分析路线的结果仍需结合原论文进行比较。


## 七、结果来源与可重复性说明

本项目对作者节点数据路线与 MyNode 自行计算路线进行区分。作者提供的预计算结果仅作为相应分析路线的输入或比较依据，不直接视为 MyNode 自行计算得到的结果。

由于网络聚类和 Bootstrap 分析可能受到随机种子、输入数据、软件版本及实现细节的影响，不同运行结果可能存在差异。因此，比较复现结果时，应结合数据来源、分析代码和具体指标进行判断，而不能仅根据聚类标签的数字是否一致来判断结果是否相同。

## 九、复现结论小结
本项目采用两条分析路线开展复现：
• 方案 A：作者节点数据路线。 使用作者提供的节点数据或相关预计算结果运行后续分析。对于能够成功生成的图表和统计结果，还需与原论文逐项比较，以确认复现程度。
• 方案 B：MyNode 自行计算路线。 基于自行计算的节点数据开展分析。虽然相关分析流程能够运行并生成图表，但自行计算得到的社区成员构成与作者结果存在差异，并可能进一步影响下游可视化和统计结果。
Louvain 社区检测具有随机性，聚类结果也可能受到输入数据、随机数设置和软件实现等因素影响。因此，方案 B 与原论文出现差异并不必然意味着代码存在错误，仍需结合具体数据、参数和结果进行判断。
总体而言，本项目完成了两条分析路线的整理与运行，并对复现过程中遇到的环境兼容性、数据处理及代码执行问题进行了相应调整。最终复现程度应以实际生成结果与原论文的逐项比较为依据。
